✨ tester-army/e2e (2508★)

一句话：让测试脚本用自然语言驱动浏览器或手机完成操作，再用传统定位器和断言核验最终结果。

  • 它是什么：e2e 是一个面向 Web 和移动应用的端到端测试框架，测试者可以让 AI agent 执行“升级到 Pro 套餐”这类自然语言步骤，并继续用 locator 和 assertion 检查页面状态。它支持 Chromium、Firefox、WebKit，以及 iOS 模拟器和 Android 模拟器；AI 步骤还会记录操作轨迹，后续运行优先回放，减少重复模型调用。

  • 能解决什么痛点：传统 E2E 测试需要为复杂交互编写大量脆弱的点击、等待和元素定位逻辑，面对页面结构变化时维护成本高。对于跨 Web、iOS、Android 的流程，团队还需要分别维护不同测试栈；该项目试图用统一的自然语言操作接口覆盖这些场景。

  • 适合谁用：需要测试真实用户流程的 Web 前端、全栈和 QA 工程师，尤其适合使用 TypeScript、Playwright 或 React Native/移动模拟器的团队。也适合希望在测试中接入自有 API Key、订阅模型或本地模型的 AI 工程团队。

  • 怎么上手：运行 npx e2e init，按提示选择 Web 或 Mobile 引擎及模型提供商；最小测试可以写成 await agent.act('upgrade the workspace to the Pro plan'); await expect(screen.getByRole('status')).toContainText('Pro');。

  • 可以用在哪些场景：

  • 测试 SaaS 产品的登录、订阅升级、账单预览和权限变更流程。
  • 在电商 Web 和移动端回归商品搜索、下单、支付前确认等跨页面流程。

  • 在每次 Pull Request 中运行自然语言验收测试，并通过 GitHub reporter 自动回传结果。

  • 技术看点：项目采用 TypeScript，并将 AI agent 操作与传统 locator/assertion 组合在同一测试文件中；Web 端基于 Playwright，移动端通过 agent-device 对接模拟器和仿真器。它还通过录制、轨迹回放、缓存和受限失败证据采集，降低重复模型调用和调试成本。

  • 近期动向与发展方向：项目在 2026 年 10 月 3-4 日集中提交了 20 条更新，说明当前处于高频迭代阶段。近期重点以稳定性和工程化修复为主，包括下载与 trace 统一 ledger、串行测试失败状态传播、敏感信息脱敏、失败证据限制、缓存一致性、Playwright 安装流程和 pnpm 兼容性；同时新增了通过 AI SDK 决策模型执行动作与断言、OAuth 接入 OpenCode Console，以及 Web 初始化脚本等能力，整体方向是继续强化 AI 测试执行、回放缓存和 Web/Mobile 双引擎基础设施。

  • AI 代理处理简单需求时容易过度设计，例如为了日期选择器引入 flatpickr、包装组件和额外样式，而 Ponytail 会优先生成原生的 ``。

  • 可以用在哪些场景：
