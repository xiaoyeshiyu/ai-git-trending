### ✨ cactus-compute/needle (4043★)

> **一句话**：Needle 2 把一个面向工具调用、设备控制和结构化抽取的 45M 参数模型压进 14MB 单文件引擎，让手机、穿戴设备、智能家居和机器人也能本地跑函数调用。

- **它是什么**：Needle 是一个 Python 包，提供 Needle 2 的推理、LoRA 微调和模型导出能力。开发者用 `pip install cactus-needle` 安装后，可以把 Python 函数或 JSON Schema 声明成工具，让模型根据自然语言请求输出受约束的结构化调用结果。它不走自由文本回答路线，而是把工具调用、设备操作和信息抽取统一成“文本输入、JSON 输出”的执行流程。
- **能解决什么痛点**：在小设备上跑工具调用模型时，常见问题是模型文件大、内存占用高、还要依赖云端推理；Needle 2 用 14MB 单文件引擎和约 28MB 会话内存，把这类能力压到边缘设备可承受的范围。另一个痛点是函数参数容易格式错、字段乱猜，Needle 会把工具 schema 编译成字节级解码 grammar，尽量让输出只落在允许的 JSON 结构和参数范围内。
- **适合谁用**：适合做手机端、智能家居、机器人、可穿戴设备本地智能交互的 Python 工程师；也适合需要把非结构化文本抽成 Pydantic 对象或 JSON 参数的后端开发者、自动化工具开发者。
- **怎么上手**：安装命令是 `pip install cactus-needle`；最小使用方式是用 `@needle.tool` 装饰一个函数，再通过 `needle.Needle(tools=[get_weather]).run("what's it like in Lagos right now?")` 让模型选择并执行工具。
- **可以用在哪些场景**：可以给智能家居 App 做本地语音指令解析，例如把“把客厅灯调暗到 30”转成 `set_lights` 调用；可以在机器人或可穿戴设备上离线判断该调用哪个设备能力，而不是把请求发到云端；也可以把发票、收据、订单文本抽取成固定字段，直接进入后续业务系统。
- **技术看点**：Needle 2 基于 Simple Attention Network，使用 Hadamard MLP、GQA attention、engram key-value memory 和多路 hyper-connections，并通过 Cactus Quants 压缩到 CQ2-bit。它还内置工具检索头，工具数量超过 5 个时只把每轮最相关的 5 个工具放进上下文，未选中的工具在 grammar 层面不可调用。
- **近期动向与发展方向**：最近提交非常集中，8 月 9 日到 11 日连续做了结构重构、依赖更新、测试增强、微调流程改进、Playground 服务和 UI、自动周发布 workflow，以及 Needle 2 Hugging Face 仓库和引擎兼容性处理。整体看项目正从研究原型向可安装、可演示、可发布的 Python 产品包推进；社区贡献也有参与，例如 Windows quickstart、类型约束和文档修正来自外部贡献者。
- **同类对比**：README 明确对比了 FunctionGemma 270M、LFM2.5 230M 和 Apple FM，Needle 2 的主打差异是体积和运行内存：在相关 benchmark 上与这些小模型互有胜负，但模型大小宣称小 5 到 70 倍，并且是 2-bit 压缩而不是 f16。
- **注意事项**：项目创建时间是 2026 年 2 月，仍然很新，虽然更新频繁但 API 和工程结构可能还在快速变化；近期有重构、依赖调整、发布流程和版本兼容提交，接入生产前需要锁定版本并做回归测试。当前 open issues 为 32，贡献者 9 人，说明已有一定关注和反馈，但成熟度还不能按长期稳定库来预期。README 内容较完整，覆盖安装、工具声明、抽取、系统事实、工具检索和置信度机制，上手材料相对充分。
