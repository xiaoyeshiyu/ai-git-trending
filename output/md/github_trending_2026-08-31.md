### ✨ Lakr233/vphone-cli (9399★)

> **一句话**：在 Apple Silicon Mac 上调用 Apple Virtualization.framework，自动下载、修补并启动一台可通过 SSH/VNC 访问的虚拟 iPhone。

- **它是什么**：`vphone-cli` 基于 PCC research VM 基础设施，在 macOS 15+ 和 Apple Silicon 硬件上启动 iPhone 虚拟机。它把 IPSW 下载与合并、固件修补、DFU 启动、SHSH 获取、恢复、CFW 安装和首次启动串成了 `vm create` 一条命令，也支持克隆、导入导出、配置和远程控制。

### ✨ p-e-w/heretic (28761★)

> **一句话**：它把“给大模型去安全对齐/去拒答”这件原本要靠人工调参和模型内部知识的活，做成了能直接跑命令自动完成的流程。

- **它是什么**：Heretic 面向 transformer 系语言模型，核心任务是通过 directional ablation（也叫 abliteration）把模型的 censorship / safety alignment 去掉。它不是单纯做一次固定处理，而是结合 Optuna 的 TPE 优化器自动搜索参数，同时尽量压低拒答率和与原模型的 KL divergence，让“去对齐”后模型尽量少伤能力。README 里明确写到它支持多数 dense 模型，也覆盖不少多模态、MoE 和部分混合架构。
- **能解决什么痛点**：第一，手工做 abliteration 需要理解模型内部并反复试参数，门槛高且耗时；Heretic 直接把这一步自动化。第二，只追求少拒答很容易把模型“改坏”，它把“少拒答”和“保留原能力”同时纳入优化目标，减少盲调带来的损失。
- **适合谁用**：做本地大模型处理、模型编辑或 interpretability 研究的 Python / PyTorch 工程师；以及在 Hugging Face 上发布、评估和复现 abliterated 模型的开源模型维护者。
- **怎么上手**：`pip install -U heretic-llm`，然后直接运行 `heretic Qwen/Qwen3-4B-Instruct-2507`。

### ✨ abhigyanpatwari/GitNexus (46119★)

> **一句话**：把代码仓库解析成可查询的知识图谱，让开发者或 AI Agent 直接看到函数调用链、依赖关系、执行流程和改动影响范围。

- **它是什么**：GitNexus 会将 GitHub、GitLab、Azure、本地仓库或 ZIP 文件索引为代码知识图谱，并提供图谱浏览、搜索和 Graph RAG 对话能力。它同时提供本地 CLI + MCP 集成，以及无需部署服务器的浏览器 Web UI，支持接入 Cursor、Claude Code、Codex、Windsurf 等开发工具。

- **能解决什么痛点**：修改一个公共函数或接口时，传统代码搜索容易遗漏跨文件、跨模块的调用方，导致类型不兼容或调用链被破坏。面对陌生的大型仓库时，开发者和 AI 也不容易快速判断某个符号的上下游依赖、所属业务流程及变更影响范围。

- **适合谁用**：需要维护 Java、Kotlin、PHP、TypeScript、NestJS 等多语言大型代码库的开发团队；希望让 Cursor、Claude Code、Codex 等 AI 编程工具获得完整架构上下文的工程师。

- **怎么上手**：在仓库根目录执行 `npx gitnexus analyze`，完成索引后执行 `npx gitnexus setup`，即可为支持的编辑器配置 MCP 和项目上下文文件。

- **可以用在哪些场景**：
  - 接手遗留项目时，通过调用图、聚类和执行流程定位核心模块及真实入口。
  - 修改后端公共服务、Java/Kotlin 路由或 NestJS 装饰器接口前，检查调用方和 API 影响范围。
  - 将本地代码库接入 AI 编程助手，让 Agent 在生成跨模块修改前查询依赖、流程和 Git diff 影响。

- **技术看点**：项目采用 Tree-sitter 做代码解析，以 LadybugDB 保存知识图谱；搜索结合 BM25、语义检索和 RRF 融合，并通过预计算的聚类、调用链和影响分析结果减少 AI 为获取上下文而进行的多轮查询。CLI 使用原生存储和解析能力，Web UI 则使用 WASM，可在浏览器内完成单仓库分析。

- **近期动向与发展方向**：项目近期保持高频开发，20 条提交集中在 2026 年 8 月 25 至 28 日，并发布了 `v1.6.10`。开发重点以稳定性和解析覆盖为主，包括修复索引目录发现、Next.js 构建产物误索引、对象处理器身份丢失、向量存储按需加载，以及完善 Java/Kotlin 常量路由、NestJS 装饰器路由和 PHP 生成客户端调用识别；同时持续进行依赖和 CI 安全更新。提交来自多位社区贡献者，说明项目仍处于快速迭代阶段。

- **同类对比**：README 将 GitNexus 与 DeepWiki 对比：DeepWiki 更偏向生成代码说明，GitNexus 则维护包含依赖、调用链、聚类和执行流程的关系图，并通过 MCP 工具向 AI Agent 提供结构化分析结果。Web UI 适合快速浏览，CLI + MCP 更适合日常开发和完整规模仓库。

- **注意事项**：项目创建时间较新，但已有 341 个 Open Issues，且近期仍有大量修复提交，使用时应关注版本变更和已知问题。CLI 依赖 Node.js、原生 Tree-sitter/LadybugDB 组件及部分 C++ 构建环境，npm 11、网络代理、可选语法包和 `onnxruntime-node` 安装可能增加上手成本；缺少部分原生预构建包时，特定语言解析能力可能不可用。Web UI 受浏览器内存限制，README 提到单机浏览器模式大约适合 5000 个文件以内的大型度有限仓库。项目采用 PolyForm Noncommercial 1.0.0 许可证，商业使用前需要确认许可边界；近期还出现带 `!` 的 `group` 行为修复提交，升级时应留意相关兼容性变化。
