### ✨ vectorize-io/hindsight (27010★)

> **一句话**：Hindsight 把智能体对话、事实和经验存进可持续检索的长期记忆中，让 Agent 在后续交互里不仅能“想起”信息，还能基于这些信息形成回答。

- **它是什么**：Hindsight 是面向 AI Agent 的长期记忆系统，提供 `retain`、`recall` 和 `reflect` 三类核心操作，分别用于保存信息、检索记忆和生成带有性格或认知倾向的回答。它支持通过 REST API、Python/Node.js/Go SDK、CLI、LLM Wrapper 以及 MCP 等方式接入现有 Agent，并支持独立部署或嵌入 Python 应用。
- **能解决什么痛点**：
  - 普通对话上下文只覆盖当前会话，Agent 无法稳定记住用户偏好、历史事实和过往决策；Hindsight 可将这些内容写入指定的 memory bank，供后续查询。
  - 单纯依赖 RAG 或知识图谱时，记忆检索、事实提炼和多轮经验积累往往需要自行拼装；Hindsight 将长期记忆存储、召回和反思式回答整合为统一接口。

- **怎么上手**：最简方式是使用 Docker 启动服务：`docker run -it --pull always --name hindsight -p 8888:8888 -p 9999:9999 -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY -v hindsight-data:/home/hindsight/.pg0 ghcr.io/vectorize-io/hindsight:latest`；客户端可执行 `pip install hindsight-client -U`，再调用 `client.retain(...)`、`client.recall(...)` 和 `client.reflect(...)`。
- **可以用在哪些场景**：

  - 在企业内部部署带长期知识记忆的销售、研究或运营 Agent，并通过 PostgreSQL、Oracle AI Database、Kubernetes 或 Hindsight Cloud 管理存储和扩展。
- **技术看点**：项目采用 Python 为主，提供 Docker、pip、Helm、嵌入式 `pg0` 和托管云等多种部署形态，并通过 SDK、REST API 和 LLM Wrapper 覆盖不同集成层。README 声称其在 LongMemEval 长期记忆基准上达到领先表现，同时支持 25+ LLM 提供商、60+ 集成和 LiteLLM 覆盖的 100+ 模型。
- **近期动向与发展方向**：项目近期非常活跃，最近 20 条提交集中在 2026-09-23 至 2026-09-24，既有 Hermes 插件 v1.1.0、coding-agents v0.7.0 等版本发布，也有 bank 别名、知识页面容错、迁移锁、向量索引和 API 边界修复。新增动画 SVG、图形导出和文档技能等内容表明项目正从核心记忆服务扩展到编码 Agent、插件生态和开发者工具链；246 位贡献者也显示出较强的社区参与度。

  - 部署 HTTP/2 服务或带认证的接口时，使用 `-h2`、`-H` 和 `-a` 模拟真实客户端请求。
- **技术看点**：项目采用 Go 实现，依赖轻、可直接下载单文件二进制；命令行参数覆盖并发、QPS、持续时间、请求构造和 CSV 输出，适合嵌入开发与运维脚本。近期提交还切换到标准库请求克隆、可停止的 `time.Ticker`，并移除过时依赖和 vendor 目录，体现出持续贴近现代 Go 工具链的维护方向。
- **近期动向与发展方向**：最近 20 条提交中有 14 条集中在 2026 年 1 月 10 日，重点是升级 Go 版本、引入 GitHub Actions CI、清理 vendor 和过时 API、修复输出格式问题、更新 README 示例及发布链接，主要属于维护和工程化改进，而非新增压测模型。提交主要由 JBD 完成，同时包含 Jaana Dogan 等贡献者的 CI 工作；结合项目创建于 2016 年、累计 51 位贡献者和 188 个 Open Issues，项目整体已较成熟，但近期活跃度更像一次集中维护。
